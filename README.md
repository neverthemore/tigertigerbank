## 🏦 Предметная область

Программа моделирует **управление личными финансами** пользователя. Основные сущности:

| Класс          | Описание                                                                 |
|----------------|--------------------------------------------------------------------------|
| `BankAccount`  | Счёт пользователя: уникальный ID, название, текущий баланс, начальный баланс (для пересчёта). |
| `Category`     | Категория операции: тип (INCOME / EXPENSE), название (например, «Зарплата», «Кафе»). |
| `Operation`    | Финансовая операция: тип, сумма, дата, описание, ссылки на счёт и категорию. |

Пользователь может:
- ➕ создавать, редактировать и удалять счета, категории, операции (CRUD);
- 📊 получать аналитику: разницу доходов/расходов за период, группировку по категориям;
- 💾 экспортировать и импортировать данные в форматах JSON, YAML, CSV;
- 🔄 автоматически пересчитывать баланс счета на основе всех операций;
- ⏱ измерять время выполнения пользовательских сценариев.

## 🎯 Применённые паттерны GoF

### 🔹 Фабричный метод (Factory Method)
Интерфейсы `BankAccountFactory`, `CategoryFactory`, `OperationFactory` и их реализации (`DefaultBankAccountFactory` и др.) изолируют логику создания объектов. Это позволяет легко менять способ генерации ID или добавлять валидацию при создании.

### 🔹 Фасад (Facade)
- `AccountFacade` — управление счетами.
- `CategoryFacade` — управление категориями.
- `OperationFacade` — управление операциями.
- `AnalyticsFacade` — аналитика.
- `ImportExportFacade` — импорт/экспорт данных.

Фасады скрывают сложность взаимодействия между сервисами и репозиториями, предоставляя простой интерфейс для консольного приложения.

### 🔹 Команда (Command)
Интерфейс `Command` с методом `execute()`. Каждый пользовательский сценарий реализован как отдельная команда:
- `CreateAccountCommand`
- `CreateCategoryCommand`
- `CreateOperationCommand`
- `GetAnalyticsCommand`
- `ExportCommand` / `ImportCommand`
- Декоратор `TimedCommand` для измерения времени выполнения.

Команды позволяют легко добавлять новые сценарии, логировать их и ставить в очередь.

### 🔹 Шаблонный метод (Template Method)
Абстрактный класс `DataImporter` определяет общий алгоритм импорта: чтение файла → парсинг → сохранение. Конкретные подклассы (`JsonImporter`, `YamlImporter`, `CsvImporter`) реализуют только этап парсинга. Это устраняет дублирование кода и упрощает добавление новых форматов.

## 🧱 Принципы SOLID и GRASP

| Принцип | Реализация |
|---------|------------|
| **Single Responsibility** | Каждый класс отвечает за одну задачу (например, `BankAccount` — только состояние, `AccountService` — бизнес-логика). |
| **Open/Closed** | Добавление новых форматов импорта через наследование от `DataImporter` не требует изменения существующего кода. |
| **Liskov Substitution** | Любая реализация интерфейса (фабрики, репозитория) может быть подставлена без нарушения работы клиента. |
| **Interface Segregation** | Интерфейсы дробные (например, `BankAccountFactory` содержит только метод `create`). |
| **Dependency Inversion** | Модули верхнего уровня зависят от абстракций, реализовано через DI-контейнер. |
| **High Cohesion (GRASP)** | Фасады объединяют тесно связанные операции (например, все операции со счетами). |
| **Low Coupling (GRASP)** | Слабая связанность благодаря использованию интерфейсов и DI. |

## 🔧 DI-контейнер

Реализован простой ручной DI-контейнер (`DIContainer`), который:
- регистрирует зависимости как синглтоны или через фабрики;
- разрешает зависимости при создании объектов.
- 
Контейнер позволяет легко заменять реализации (например, переключиться на репозиторий с БД) и упрощает тестирование.

🧪 Модульное тестирование
JUnit 5 для всех тестов.

Mockito для изоляции фасадов и команд.

Покрытие ключевой логики >85%.

Тесты проверяют:

корректность работы фабрик;

выполнение команд;

бизнес-правила сервисов (запрет отрицательных сумм, проверка существования счёта и категории);

пересчёт баланса с учётом начального баланса;

работу импорта/экспорта (с использованием временных файлов).

Все тесты проходят успешно на Java 25 благодаря флагу -Dnet.bytebuddy.experimental=true.

📁 Работа с файлами
JSON — JsonImporter / JsonExporter (Jackson)

YAML — YamlImporter / YamlExporter (Jackson)

CSV — CsvImporter / CsvExporter (ручной парсинг)

Все классы импорта наследуются от DataImporter (шаблонный метод), а экспорт реализует интерфейс DataExporter. Это обеспечивает лёгкое расширение на другие форматы.

✅ Функциональные требования
Создание, редактирование, удаление, получение счетов, категорий, операций.

Аналитика: разница доходов/расходов за период, группировка по категориям.

Импорт/экспорт JSON, YAML, CSV.

Автоматический пересчёт баланса при несоответствии.

Измерение времени выполнения сценариев (декоратор TimedCommand).

🚧 Проблемы при расширении
Добавление новой сущности (например, «Бюджет») потребует создания новых фабрик, фасадов, команд и модификации аналитики.

Изменение общего алгоритма импорта (например, добавление транзакционности) затронет базовый класс DataImporter и все его наследники.

Новые пользовательские сценарии легко добавляются через новые команды, но могут потребовать изменений в фасадах, если они затрагивают несколько сущностей.

Поддержка новых форматов — легко (новый класс-наследник DataImporter), но если формат требует особого парсинга, возможно дублирование логики.

💡 Почему абстракции улучшили дизайн
Фабрики отделяют создание объектов от бизнес-логики, упрощают тестирование и позволяют легко менять способ создания (например, генерировать ID по-другому).

Фасады скрывают сложность взаимодействия между сервисами, делая клиентский код простым и понятным.

Команды инкапсулируют пользовательские сценарии, что позволяет легко добавлять новые, логировать, ставить в очередь и измерять время.

Шаблонный метод устраняет дублирование кода при импорте из разных форматов и обеспечивает единый алгоритм.

DI-контейнер обеспечивает слабую связанность и упрощает конфигурирование.

Благодаря этому код стал гибким, тестируемым и готовым к изменениям.

Требования
Java 25 (или 17+ с флагом экспериментальной поддержки)

Сборка и запуск
bash


# Сборка
mvn clean compile

bash
